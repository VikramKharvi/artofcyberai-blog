Build GPT from the data pipeline up.

The shortest path to understanding a transformer is to make every tensor earn its place.

01

The baseline

Begin with the prediction problem, not the architecture.

Take a token sequence, sample a window, and create two aligned tensors: the input and the same sequence shifted by one position. Every position becomes a training example whose target is the following token. Cross-entropy measures how much probability the model assigned to those targets.

A simple table of next-token counts is a useful first model. It cannot use long context, but it validates the data path, loss, sampling, and generation loop. The transformer should arrive only after the baseline makes the missing capability obvious.

02

Attention

Attention lets each token gather the context it needs.

Token and position embeddings create the initial vectors. Learned query, key, and value projections then assign three roles: what a position seeks, what it offers, and what information it contributes. Query-key similarity becomes a set of weights over value vectors.

For autoregressive generation, a causal mask blocks future positions before the softmax. Scaling keeps large dot products from making the distribution unstable. Multiple heads repeat the operation in parallel, allowing the block to represent different relationships without prescribing what each relationship must be.

Attention is controlled communication between positions.
03

The block

Communication alternates with local computation.

Multi-head attention mixes information across positions. A feed-forward network then transforms each position independently. Residual connections preserve a direct path for information and gradients, while layer normalization keeps activations in a workable range. Repeating this block creates depth.

Dropout regularizes the network during training and disappears during evaluation. The final normalization and linear language-model head map hidden vectors back to vocabulary logits. Weight tying can reuse the token embedding matrix, connecting how the model reads and predicts tokens.

04

The loop

A trustworthy training loop stays deliberately boring.

Sample reproducible batches, run the forward pass, compute loss, clear gradients, backpropagate, update parameters, and measure a held-out split on a fixed schedule. Log enough state to reproduce a divergence: seed, data version, step, learning rate, configuration, and checkpoint.

Generation is the same model used one position at a time: crop to the available context, compute logits for the final position, sample a token, append it, and repeat. Once this minimal system works, optimizations can change speed without changing the reference behavior.
