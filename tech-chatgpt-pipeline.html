Tech note 05 / Assistants

How a base model becomes an assistant.

A conversational model is produced by a pipeline: encode text, learn broad patterns, shape behavior, allocate reasoning, connect tools, and build the interface.

01

Pretraining

First build a simulator of token sequences.

Raw documents are cleaned, filtered, deduplicated, mixed, and converted to tokens. The transformer receives windows of those tokens and learns to predict each next position. Across enough examples, the network develops representations that support language, factual associations, code, and many reusable patterns.

The resulting base model continues text; it does not yet carry a reliable concept of a helpful assistant. It may imitate any mode present in its data. The next stage must teach the conversational role and the boundaries expected by the product.

02

Post-training

Examples and feedback shape the interaction policy.

High-quality conversations demonstrate how to follow instructions, structure an answer, ask for missing information, and decline unsafe requests. Training on those demonstrations makes the assistant role familiar. Preference feedback then supplies comparisons between possible responses.

The data design matters as much as the optimization method. Narrow examples produce narrow behavior; inconsistent judgments create unstable objectives. Difficult cases should be represented explicitly, and evaluation must separate factual quality, usefulness, style, safety, and task completion rather than collapsing them too early.

03

Reasoning

More useful work can happen at generation time.

Some problems benefit from intermediate computation, verification, or repeated attempts. A system can allocate more tokens and more tool calls to difficult tasks instead of treating every request as one immediate response. The key is to connect that extra work to checks that detect progress rather than reward length.

Tools extend the action space beyond text. A model can calculate, execute code, inspect a workspace, or operate an application through typed interfaces. Each action should return an observation, and the runtime should preserve permissions, budgets, and the causal record needed to audit the result.

04

The product

Multimodality and interface design complete the system.

Images, audio, and other inputs can be mapped into representations the language backbone can use; generated tokens or specialized decoders can drive multiple output forms. But additional modalities also introduce new preprocessing, timing, evaluation, and safety requirements.

The final assistant is therefore a stack: tokenizer, base model, post-training policy, context manager, reasoning budget, tools, modality adapters, checks, and user interface. Improving one layer can expose a bottleneck in another. The right unit of engineering is the entire loop from request to verified outcome.
